# DVWA Integration

## Objective

Deploy the Damn Vulnerable Web Application (DVWA) inside a Docker container on **Ubuntu 2 (24.04 LTS)** and integrate its Apache access logs with the Wazuh Agent. This enables SentinelForge-SOC to monitor, collect, and analyze web application attacks such as Cross-Site Scripting (XSS), SQL Injection, Command Injection, and Local File Inclusion.

# Step 1 - Install Docker

Update Ubuntu packages.

```bash
sudo apt update
```

Install Docker.

```bash
sudo apt install docker.io -y
```

Enable Docker.

```bash
sudo systemctl enable docker
```

Start Docker.

```bash
sudo systemctl start docker
```

Verify Docker installation.

```bash
docker --version
```

Verify Docker service.

```bash
sudo systemctl status docker
```

Expected Result

```
Active: active (running)
```

---

# Step 2 - Create Apache Log Directory

Create a directory on the host system to store Apache logs generated by DVWA.

```bash
sudo mkdir -p /var/log/dvwa
```

Verify.

```bash
ls -ld /var/log/dvwa
```

---

# Step 3 - Deploy DVWA

Run the DVWA Docker container.

```bash
sudo docker run -d \
-p 80:80 \
-v /var/log/dvwa:/var/log/apache2 \
--name dvwa \
vulnerables/web-dvwa
```

Verify.

```bash
sudo docker ps
```

Expected Result

```
dvwa
Up
0.0.0.0:80->80/tcp
```

# Step 5 - Verify Apache Logging

Open another terminal.

Monitor Apache logs.

```bash
sudo tail -f /var/log/dvwa/access.log
```

Browse different DVWA pages.

Expected Result

```
GET /
GET /login.php
GET /index.php
```

This confirms Apache is generating logs.

---

# Step 6 - Configure Wazuh Agent

Edit the agent configuration.

```bash
sudo nano /var/ossec/etc/ossec.conf
```

Add:

```xml
<localfile>
    <log_format>apache</log_format>
    <location>/var/log/dvwa/access.log</location>
</localfile>
```

Save the file.

Restart the Wazuh Agent.

```bash
sudo systemctl restart wazuh-agent
```

Verify.

```bash
sudo systemctl status wazuh-agent
```

# Troubleshooting

## Problem 1

```
Conflict.
The container name "/dvwa" is already in use.
```

Cause

The DVWA container already existed.

Solution

```bash
sudo docker start dvwa
```

instead of

```bash
docker run
```

---

## Problem 2

Apache log not found.

```
/var/log/dvwa/access.log
No such file or directory
```

Cause

The Docker volume was not mounted.

Solution

Remove the old container.

```bash
sudo docker rm -f dvwa
```

Recreate it.

```bash
sudo docker run -d \
-p 80:80 \
-v /var/log/dvwa:/var/log/apache2 \
--name dvwa \
vulnerables/web-dvwa
```

---

## Problem 3

Apache logs generated but Wazuh receives nothing.

Solution

Restart the Wazuh Agent.

```bash
sudo systemctl restart wazuh-agent
```

Verify.

```bash
sudo tail -f /var/log/dvwa/access.log
```

# Lessons Learned

- Docker containers require persistent volume mapping to expose logs to the host system.
- Wazuh can only monitor log files accessible from the host operating system.
- Apache access logs provide the primary telemetry source for web application attack detection.
- Verifying log generation before configuring Wazuh significantly simplifies troubleshooting.
